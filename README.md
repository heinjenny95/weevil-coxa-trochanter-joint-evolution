# Weevil coxa-trochanteral joint evolution

Analysis code accompanying the manuscript **Evolutionary diversification of
the biological screw joint in weevils**.

**Release v1.4.0 - study analysis and peer-review package.** This release adds
a tested installation and reviewer example, archived preprocessing source,
missing mask-boundary QC, reconstructed helix inputs and downloadable atlas,
mask and phylogenetic-inference inputs. It builds on the unchanged submission
release [v1.3.2](https://github.com/heinjenny95/weevil-coxa-trochanter-joint-evolution/releases/tag/v1.3.2).
The numerical reference tables remain unchanged.

These are study-specific R and Python analysis scripts. Start with the
[reviewer example](#reviewer-example), [input downloads](#input-downloads) and
[Nature checklist documentation map](docs/NATURE_CODE_CHECKLIST.md).

The repository documents selected preprocessing and Deformetrica atlas steps
and contains the downstream statistical and morphometric analysis workflows used to study trochanter shape,
screw joint geometry, joint typology, phylogenetic history, allometry and
broad ecological associations across Curculionoidea. It also includes the
reproducible renderers and shared visual style for the quantitative publication
figures. Photographic, tomographic and manually assembled anatomical panels are
distributed as figure assets rather than regenerated by these R workflows.

## Repository contents

- `scripts/analysis/atlas_pca_workflow`: PCA extraction, morphospace
  clustering and family disparity.
- `scripts/analysis/allometry_analysis`: specimen-level allometry workflow.
- `scripts/analysis/deformetrica_workflow`: deterministic-atlas configuration,
  ordered 68-subject dataset XML, portable runner and an output-free Jupyter
  workflow. The aligned VTK meshes, initial template and archived outputs are
  available in the versioned atlas release asset linked below.
- `scripts/analysis/mesh_preprocessing`: archived batch remeshing/cleanup and
  three-landmark GPA alignment used to prepare trochanter meshes.
- `scripts/analysis/coxa_wall_analysis`: whole-volume three-dimensional coxal
  wall-thickness, coxa-size and wall-opening analyses. Older central-section
  scripts are retained only as an exploratory historical record.
- `scripts/analysis/ecology_analysis`: exploratory ecological association
  tests.
- `scripts/analysis/figure_rendering`: shared publication style and the
  renderer for clustering, coxal-wall and ecological figures.
- `scripts/analysis/phylogeny_workflow`: alignment-subsetting code, the
  resulting study tree and downstream tree preparation, explicit calibration
  provenance and an updated 195 Ma calibration sensitivity workflow. The study inference alignment, partition files and IQ-TREE
  records are supplied in the versioned phylogeny release asset.
- `scripts/analysis/phylogenetic_comparative_analysis`: phylogenetic
  comparative analyses, including phylogenetic signal, evolutionary models,
  PGLS, phylogenetic ANOVA, ancestral-state reconstruction and targeted
  phylogenetically informed allometry tests.
- `scripts/analysis/joint_typology`: joint-character coding, joint-type
  assignment and theoretical character-combination summaries.
- `scripts/analysis/screw_geometry_analysis`: robust circular 3D helix fitting,
  the original Cinema 4D/Python axis-and-circle implementation retained for
  audit, conditional measurement bootstrap, downstream shape-geometry models
  and joint-type tests.
- `scripts/analysis/revision_audit`: reproducible specimen-to-proxy-tip mapping
  and submission-consistency checks.
- `data/metadata`: analysis identifiers and the explicit specimen-to-proxy-tip
  mapping used to audit the phylogenetic analysis unit. The specimen key also
  records the exact public `radar_filename`, including `_sp` suffixes and the
  deposited legacy filename `Rynchites_cupreus`; collection and voucher
  metadata are not part of this release.
- `data/publication_figures`: all 38 final raster figures embedded in the
  regular manuscript, with stable paths, dimensions and SHA-256 checksums.
- `data/supplementary_source_data`: the complete CSV payload for
  Supplementary Tables 1-40, including morphospace, geometry, allometry,
  coxal-wall, joint-typology, ecology and phylogenetic robustness outputs, plus
  calibration-sensitivity source data linked to the robustness tables. The
  normalized `_table_file_map.csv` gives one row per table-file relationship,
  including the source files shared by Tables 10 and 11.
- `data/screw_geometry`: all 64 robust helix fits, 12,800 bootstrap draws, the
  63-specimen main analysis dataset, descriptive QC diagnostics and a compact
  interpretation audit.
- `scripts/code_manifest.csv`: file sizes and SHA-256 checksums for the
  released scripts.
- `r_package_inventory.txt` and `python_requirements.txt`: detected software
  dependencies.

## Reviewer example

### System requirements and tested versions

The v1.4.0 reviewer package was tested on Windows 11 Enterprise, version 10.0.26200, using
R 4.5.2 and CPython 3.12.14. The test workstation had an AMD Ryzen 9 7950X
(16 cores, 32 logical processors) and approximately 128 GiB RAM. This is the
measured test configuration, not a minimum hardware requirement. The tabular
reviewer example and helix fitter use the CPU and require no GPU, cluster,
Cinema 4D, scanner or other special hardware. Minimum RAM was not benchmarked.
Full-volume image processing and atlas estimation are outside this small
example and have substantially different resource requirements.

The R dependency names are in `r_package_inventory.txt`; the complete package
versions in the verified environment are in
`docs/tested_environment/R_packages.csv`. In particular, **RRPP 2.1.2 and
geomorph 4.0.10 must be retained to reproduce the released multivariate
allometry results**. Installing current CRAN versions RRPP 2.2.0 and geomorph
4.1.1 changed numerical results in the validation. The installer restores the
historical versions from CRAN archives, including their rgl/jpeg dependencies.
Other tested package versions are a record of the validation environment, not
a claim that every other version is incompatible. Linux and macOS were not
tested in this audit. R source dependencies may require platform build tools
there; the tested Windows installation used CRAN binaries plus the two
historical pure-R source packages and did not require Rtools.

`python_requirements.txt` is an inventory across separate workflows, including
external/legacy software. Do not install it as a single environment: the
Deformetrica 4.3.0 atlas workflow requires its own compatible environment.
For the standard-Python helix fitter, use the tested requirements below.
Cinema 4D 2026 supplies its own `c4d` module; it is not a pip dependency.
See the original workflow READMEs for the upstream software and parameters.

### Install R dependencies

Install R 4.5.2, make `Rscript` available, then run from this repository root:

```text
Rscript --vanilla scripts/install_R_dependencies.R
```

This installs into `.reviewer-library` without replacing an existing user
library. An optional first argument chooses a different library directory.
The installer verifies that dependencies load and the two historical versions
were installed. It saves the installed versions and `sessionInfo.txt` in that
library. Internet access is required for installation, not for the R example.

A clean dependency installation on the test workstation took approximately
two minutes, excluding the installation of R itself. Download speed and
platform affect this timing; the exact recorded value is in
`docs/tested_environment/validation_summary.json`.

### Run on the bundled study data

```text
Rscript --vanilla scripts/run_reviewer_demo.R
```

Optional arguments select an output directory and the installed library:

```text
Rscript --vanilla scripts/run_reviewer_demo.R /path/to/new-output /path/to/R-library
```

The example runs seven actual study workflows: specimen-to-proxy mapping,
shape versus geometry regressions, full-shape allometry, univariate and
multivariate phylogenetic allometry, family disparity, and downstream coxa-wall
statistics. It starts from the released derived inputs; it does not repeat
scanning, segmentation, atlas estimation or manual landmark placement.

Expected output in `reviewer-demo-output/`:

- `verification.csv`: 25 reference-table checks, all with `passed = TRUE`;
- `timings.csv`, `sessionInfo.txt` and separate per-workflow logs;
- regenerated regression/allometry/disparity/coxa tables and associated figures;
- a final console line `PASS: 25 reference tables verified ...` and exit code 0.

The example checks 68 mapped specimens, 63 main geometry trajectories and
15 shape versus 14 geometry proxy tips through the matching released tables.
Numbers are compared with absolute tolerance 1e-10 plus relative tolerance
1e-7. Only shared columns are compared; newly added QC metadata are not
represented as original release values. Coxa comparison uses the released
`all_masks` rows. The boundary-exclusion rows newly enabled by the recovered
QC are exported separately and have no v1.3.2 reference rows.

Allow approximately half a minute on the documented workstation, excluding
installation. Actual timings are recorded in the validation summary.
Publication renderers were also tested separately; image bytes need not be
identical across plotting/font versions even when source numbers agree.

### Standard-Python helix checks

```text
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r docs/tested_environment/requirements-helix-tested.txt
```

On POSIX systems the executable is `.venv/bin/python`; that platform was not
tested. Run the Windows test command from the repository root:

```text
.\.venv\Scripts\python.exe -m unittest discover -s scripts/analysis/screw_geometry_analysis -p test_fit_helical_paths.py -v
```

Expected result: three successful tests, final `OK`, exit code 0. A fresh
dependency installation took about 20 seconds and the tests about 7 seconds
including imports on the documented workstation. The test covers parser
behaviour, recovery of known helix parameters and resistance to one outlier.
In addition, all 64 observed paths reconstructed from the released point table
were refitted with zero bootstrap replicates: winding angle, fitted pitch,
radius, helix RMS and endpoint axial span matched the released values exactly
at stored precision. This does not repeat the 12,800 bootstrap fits or test
independent landmark-placement repeatability.

### Using other input data

The scripts are study-specific. Their input column names, specimen identifiers
and proxy-tip mappings are part of the analysis definition. Use the command-line
paths documented in the workflow READMEs, preserve the required columns and
check identifier matches before analysing a different dataset. For example:

```text
Rscript scripts/analysis/screw_geometry_analysis/screw_geometry_extraction_workflow.R PCA.csv geometry.csv new-output
Rscript scripts/analysis/allometry_analysis/run_unified_phylogenetic_allometry.R specimen-table.csv specimen-key.csv tree.tre new-output
```

For helix fitting, supply one ordered Cinema 4D-style landmark CSV per specimen,
with the `Landmarks` count row and X/Y/Z columns, as demonstrated by the bundled
parser test. Run `fit_helical_paths.py INPUT_DIRECTORY NEW_OUTPUT_DIRECTORY`;
add `--bootstrap 200 --seed 20260810` for the study's conditional bootstrap.
Do not silently reuse the study's taxonomic mappings or inclusion definitions
for an unrelated dataset.

## Running the analyses

The scripts are a transparent analysis record rather than a containerized
one-command pipeline. The released tables, trees and derived outputs support
the downstream statistical analyses and publication figures. Earlier
raw-to-derived stages additionally require inputs that are not all
redistributed in this repository; see [Reproducibility scope](#reproducibility-scope).

1. Clone this repository.
2. Use the R installer or workflow-specific Python environment described above;
   the root Python inventory spans separate incompatible upstream environments.
3. Replace placeholder roots such as `<MANUSCRIPT_PROJECT_ROOT>`,
   `<KERNEL_WIDTH_PROJECT_ROOT>` and `<BEETLE_JOINTS_ROOT>` with local paths, or
   pass the command-line inputs documented by the individual script.
4. Run the workflow-specific scripts from `scripts/analysis`. The
   Deformetrica workflow has its own detailed README and notebook entry point.

The quantitative publication figures can be regenerated from the repository
root with:

```text
Rscript scripts/analysis/figure_rendering/render_foundational_publication_figures.R
Rscript scripts/analysis/screw_geometry_analysis/render_publication_style_figures.R
Rscript scripts/analysis/figure_rendering/render_supplementary_figure_7.R <REPOSITORY_ROOT> [<MANUSCRIPT_ROOT>]
Rscript scripts/analysis/figure_rendering/render_supplementary_figure_15.R <REPOSITORY_ROOT> <PCM_MAIN_OUTPUT> [<MANUSCRIPT_ROOT>]
```

The intended generic project layout is:

```text
<MANUSCRIPT_PROJECT_ROOT>/
  analysis_data/
    Input/
    Results/
```

Some scripts create diagnostic graphics as analysis byproducts. These are not
the final publication layouts.

### Phylogenetic analysis unit

The broad comparative analyses use 15 taxonomic proxy tips because the available
Curculionoidea backbone does not contain most of the 68 sampled genera. Several
sampled genera can therefore contribute to one proxy tip, and continuous
measurements are averaged within that tip before phylogenetic modelling. These
labels must not be interpreted as exact genus matches. The explicit mapping is
generated by `scripts/analysis/revision_audit/build_proxy_mapping.R` and is
distributed with the supplementary source data. Geometry-dependent comparative
analyses use 14 matched proxy tips from the 63-specimen main dataset. Results
are reported across alternative trees because the backbone is not sufficiently
resolved to support topology-independent claims.

Continuous ancestral-state reconstruction follows the same sampling rule:
PC1-PC5 and centroid size use the 15-tip shape-only dataset, whereas absolute
winding angle and endpoint-based axial span use the 14-tip main geometry
dataset. Supplementary Table 24 exports raw-scale node estimates, variances and
95% intervals for all eight traits. Extended Data Figure 5 uses standardized
scores only for colour mapping and prunes each panel to its numerical
trait-specific tip set; the missing geometry values for the Nemonychidae proxy
tip are not used to force the five shape maps onto the 14-tip tree. All
`fastAnc` estimates and `contMap` visualizations are conditional on Brownian
motion (BM), recorded explicitly as `reconstruction_model = BM`; this common
reconstruction assumption is not a model-selection result. In particular, the
exploratory univariate comparison ranks OU above BM for axial span on the
primary tree, while tree-sensitive rankings do not identify a robust general
evolutionary process.

The primary comparative tree is `data/phylogeny/P01_Trees/01_primary_tree_grafen.tre`.
Its Grafen branch lengths encode relative node depth and are not geological
ages. Fourteen additional topology and branch-length representations, including
the archived historical 223 Ma calibration and alternative calibration
settings, are retained for sensitivity analyses; no divergence-time estimate is
made from these trees.

### Allometry analysis scope

The primary multivariate allometry test uses all non-zero atlas PC axes and
therefore represents the complete atlas-derived shape space. Because atlas
shapes were normalized for scale before PCA, the isometric null is a zero
multivariate shape slope with log centroid size. Analyses restricted to
PC1-PC5 are retained only as anatomical sensitivity analyses; these five axes
are used elsewhere in the manuscript for interpretable visualization of the
dominant deformations.

The phylogenetically informed multivariate allometry analysis likewise uses
all non-zero atlas PC axes directly in an RRPP model with the phylogenetic
covariance matrix. Its one-dimensional fitted projection is produced only for
visualization and is not used as the response variable for inference.

### Multivariate evolutionary-model reliability

Multivariate BM, OU and EB fits to PC1-PC5 and PC1-PC4 use the 15 shape-only
proxy tips. Optimizer convergence and Hessian reliability are recorded
separately. Raw AIC values are retained for transparency, but reported model
rankings and Akaike weights use only fits for which the optimizer converged and
the Hessian diagnostic was reliable. Under the primary Grafen tree, BM and EB
are reliable for both shape representations and BM has the lower AIC; the
PC1-PC5 OU optimizer converges but has an unreliable Hessian, while PC1-PC4 OU
fails. These small-sample comparisons remain exploratory.

Axis-specific phylogenetic allometry is generated by the dedicated unified
workflow in `scripts/analysis/allometry_analysis`. It uses the log of the
proxy-tip mean centroid size, 15 shape tips and 14 geometry tips matched from
the 63-specimen main dataset before aggregation. Pagel's lambda is estimated by
maximum likelihood within [0, 1]; no fixed-lambda fallback is used.

## Reproducibility scope

The seven-workflow R example verifies 25 released reference tables from the
checked-in derived inputs. Windows 11/R 4.5.2 and the full tested R package
versions are recorded under `docs/tested_environment`; the standard-Python
helix fitter was tested with Python 3.12.14. R 4.5.2/Python 3.12.8 were the
original v1.3.2 release-check versions. Tested component environments should
not be interpreted as one combined environment for all upstream applications.

### Atlas outputs to PCA

Extract the atlas ZIP so that its `atlasing` directory is available, then run:

```text
Rscript scripts/analysis/atlas_pca_workflow/r/extract_pca_scores_with_specimen_ids.R atlasing/Atlas_Momentas.txt atlasing/data_set.xml new-pca-output
```

All 4,624 numerical scores (68 axes for 68 specimens) and the eigenvalue and
variance table match v1.3.2 exactly at stored precision. The historical XML
identifier `t_pseudonastus_trochanter_aligned` is normalized to the released
`t_pseudonasutus_trochanter_aligned`; the extractor records it in
`specimen_identifier_corrections.csv`. No PCA number is changed.

The archived log records tolerance 0.0001, last reported iteration 51 and
32 minutes 44 seconds of estimation. The log reports `GpuMode.KERNEL` whereas
the saved XML contains `kernel-device=cpu`; historical hardware use is not
established by the XML alone. The Deformetrica 4.3.0 workflow and recorded
configuration are documented under `scripts/analysis/deformetrica_workflow`.
This release verifies the output-to-PCA step; it does not claim a new atlas
optimization run or a fully frozen historical Deformetrica environment.

### Helix inputs and fitting

`data/reviewer_support/helix_traces` contains 64 ordered inputs reconstructed
from the already released observed XYZ coordinates and point names. The units
are copied from the released metrics. These files are not claimed to be the
original Cinema 4D exports, and original normal vectors are not reconstructed.
The robust fitter uses the observed coordinates. From the repository root:

```text
python scripts/analysis/screw_geometry_analysis/fit_helical_paths.py data/reviewer_support/helix_traces helix-rerun-output --bootstrap 0 --no-specimen-plots
```

The no-bootstrap refit of all 64 paths took about 74 seconds on the documented
workstation. Winding angle, pitch, radius, helix RMS and endpoint axial span
matched the released point estimates exactly at stored precision. Use
`--bootstrap 200 --seed 20260810` to request the study bootstrap; its 12,800
released draws were not regenerated in this validation. The input-repackaging
script is `reconstruct_helix_traces.py` in the same script directory.

### Earlier processing and limits

The archived Cinema 4D `Obj_Processing.py` source is supplied with a portable
input-path override. Its documented target is 10,000 polygons, three smoothing
iterations at alpha 0.40 and disabled hole closing. Its syntax was checked;
Cinema 4D execution and the historical preprocessing log were not revalidated.
The original Checkpoint/Morphologika landmark files are not bundled. They are
needed to repeat the earlier landmark-based alignment, but the aligned meshes
and initial template needed to start the atlas are now available in the atlas
asset. Processed joint-surface meshes are available on RADAR4KIT.

Original coxa masks now accompany the release. The R example verifies the
published all-mask and lower-tail statistics and supplies the three recovered
boundary flags needed by the existing exclusion sensitivity. Full local-
thickness extraction was not rerun. IQ-TREE 2.4.0 inputs and run records are
available, but inference was not repeated. The complete broad PCM/ecology
workflow and every bootstrap analysis were not rerun in this validation.
These limits distinguish tested stages from accessible but untested stages;
this is not a claim of a new scan-to-results experiment.
